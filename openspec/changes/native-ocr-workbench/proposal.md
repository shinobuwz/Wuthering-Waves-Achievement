## 为什么

Native 版的 OCR 已经支持“当前分类扫描”和“全量扫描所有分类”，但目前扫描流程、取消状态、进度文本和异常提示都直接放在 `MainWindow` 中。随着全量扫描包含一级分类切换、二级分类发现、列表滚动、分页 OCR 和最终预览，主页面操作区会越来越拥挤，扫描过程中用户也只能依赖底部提示文字了解状态。

需要一个专用的 OCR 扫描工作窗口，将长时间任务的状态、进度、取消和结果摘要集中起来，同时不重新引入 Python 版的顶层 OCR Tab。

## 变更内容

- 新增 Native OCR 专用扫描工作窗口。
- “OCR 自动扫描当前分类”和“OCR 全量扫描所有分类”按钮改为打开对应模式的工作窗口。
- 在工作窗口中显示当前阶段、分类、页码、已识别数量、未匹配数量和可恢复警告。
- 支持取消扫描，并保证取消或失败时不写入工作区进度。
- 扫描完成后继续复用现有 OCR 预览窗口和 `AchievementWorkspace.ApplyOcrPreviewAsync` 事务写入流程。
- 保留当前主页面，不新增顶层应用 Tab；Python 版继续保持可运行。

## 功能（Capabilities）

### 新增功能

- `native-ocr-workbench`：Native OCR 扫描任务窗口、进度反馈、取消和结果摘要。

### 修改功能

- `native-ocr-scan`：将扫描编排从主窗口交互代码中抽离为可报告进度的任务入口；不改变当前分类扫描和全量扫描的业务语义。

## 影响

- **Native UI**：新增 OCR 工作窗口，并调整主窗口两个 OCR 按钮的启动方式。
- **Native OCR 编排**：需要统一当前分类和全量扫描的进度、取消、异常和恢复状态。
- **Native Core/Tests**：增加扫描进度事件、运行结果和取消/失败契约测试。
- **数据安全**：扫描期间不修改 workspace；只有用户在已有预览窗口中明确接受后才应用 OCR 结果。
